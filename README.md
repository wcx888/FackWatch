# FackWatch

**让小米手表也能收到「双开微信（手机分身）」的消息提醒。**

手表端微信登录主号之后，手机分身里那个微信的消息在手表上就不再提醒——因为手表会按包名 `com.tencent.mm` 把手机转发过去的微信通知丢掉。FackWatch 是一个 LSPosed 模块，在**小米运动健康**进程里改写这条通知的转发身份，手表就不会再丢。

**v1.2.1 起只需安装一个 APK：主程序自身同时提供通知使用的应用身份，不再需要单独的身份壳。**

> 只作用于「小米运动健康 → 手表」这条通知链路；不修改微信、不改通知栏、不联网；没有常驻后台服务，只在通知产生时执行一次。

---

## 原理

```
双开微信 (user 999) 发通知
        │
        ▼
com.mi.health  NotifySyncService   ← FackWatch 在这里 hook
        │  把 StatusBarNotification 改写成由 FackWatch 主程序提供的通知身份
        ▼
蓝牙 → 手表          ← 手表认这个身份，不再丢弃
```

单 APK 完成全部工作，不再有第二个需要安装或隐藏的应用。

## 功能

- 手表上以「微信双开」+ 黄色双开角标显示副号消息；手表端图标为单层绿底、透明圆角
- 桌面 App「FackWatch」提供**运行自检**和**发测试通知**
  - 自检项：小米运动健康的通知使用权、FackWatch 的通知权限、模块加载状态、各项 Hook 状态
  - 发测试通知后，可查看手机端是否观察到了这次通知改写
- **两种通知模式都支持**：
  - 「同步手机全部通知」：所有应用通知一律同步
  - 「自定义消息通知」：只同步勾选的应用，模块会在小米运动健康读取名单时自动补入所需包名，不需要手动添加
- 消息可在手表上查看；回复仍需在手机上操作

## 环境要求

| 项 | 要求 |
|---|---|
| 手机 | 小米 / Redmi，**已 root**（KernelSU 或 Magisk） |
| 框架 | 支持 **libxposed API 102** 的 LSPosed（Zygisk） |
| 配套 App | 小米运动健康（当前验证版本 **3.59.2**） |
| 手表 | 小米手表 S4（通知链路已验证；其它型号未验证） |
| 微信 | 主号在手表和手机主用户；副号在手机分身 / 应用双开，Android 用户 ID `999` |
| 测试机 | 小米 17 Pro Max / OS4（HyperOS 4） |

不满足这套环境，安装也不会生效。

## 安装与升级

1. 安装 `dist/FackWatch-1.2.1.apk`（或从 Release 页下载附件）。
2. 在 **LSPosed → 模块**中启用 FackWatch；作用域只勾 **小米运动健康**（`com.mi.health`）。
3. 从旧双 APK 版升级时，由于包名不同，新旧主程序会并存，请停用旧模块；已安装单 APK 版的用户可直接覆盖升级。
4. 重启手机，打开一次小米运动健康。
5. 打开 FackWatch，点「运行自检」和「发测试通知」，按提示允许通知，然后在手表上确认收件。

## 已知限制

- 只对**手机分身 / 应用双开**（user 999）的微信生效；手表微信必须登录**主号**
- **小米运动健康升级后模块可能失效**，当前仅在 3.59.2 上验证，升级后需要重新适配
- 手表如果缓存过同包名的图标，升级后可能继续显示旧图标
- 自检中的「已触发包名改写」只表示手机端已处理该通知；手表是否收到以实机显示为准
- 副号消息可以查看，但回复仍需在手机上操作
